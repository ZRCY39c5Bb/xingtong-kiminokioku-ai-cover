## 1 项目速览

### 1.1 目标

把《女神异闻录3》片尾曲「你的记忆」（キミの記憶）做成 **星瞳（腾讯虚拟偶像）音色的 AI 翻唱**，并配套一支 **P3 平涂风格的同人 MV**。

三件事同时成立才算完成：

1. 干净人声 → 换声 → 混音，产出一条完整可听的翻唱音轨；
2. 一套能直接剪的 MV 视觉素材（主视觉 + 小人动画 + 字幕）；
3. 全流程本地跑通，不依赖付费在线服务。

### 1.2 最终成果

| 类别 | 产物 | 状态 |
|---|---|---|
| 人声分离 | A/B/C/D 四条分轨，5:57.70，44.1kHz 立体声 32bit float | ✅ 完成，A+D 与原曲逐采样互补（相关系数 **1.00000000**） |
| 音色转换 | so-vits-svc 4.0 + 星瞳 `G_99200`，20 秒样片 + 全曲两版（聚类 0.6 / 0.7） | ✅ 完成 |
| 主视觉 | 蓝色星瞳（2048×1152）、红色星瞳（1920×1080） | ⚠️ 蓝版成立；红版背景与服装有缺陷，见 6.3 |
| 字幕工程 | 能量包络切句脚本 `detect_phrases.py` | ✅ 脚本可跑通，未接成 SRT |
| MV 动画 | 哩布试验提示词包 + 本地 ComfyUI 重绘方案 | ⏳ 到方案与提示词为止，未出图 |
| 成片混音 | 人声 + 伴奏 + 后期对齐 | ⏳ 未做 |

### 1.3 一句话结论

**分离和换声这两段已经跑通，卡点不在技术而在「素材干净度 → 高音表现」这条链上。**
现有星瞳 so-vits 4.0 权重能出可听的成品，但副歌高音偏薄；要显著提升只能换 DDSP 自训模型（见 2.3 路线 D/E）。

| B | 星瞳 sovits 4.0 本地权重（3 个 checkpoint） | 本地 `.pth` | 百度网盘 `pwd=d9lh`，常用 `99200` | 作者：B站专栏 `814460614067879959` |
| C | 星瞳 RVC 模型（`.pth` + `.index`） | 本地 | `github.com/InkStain258/Xingtong_RVC` | 2025-06，作者自评「效果一般」 |

### 2.2 三个模块的方案对比

**模块一：人声分离**

| 方案 | 位置 | 工具要求 | 6:39 全曲耗时 | 干声质量 | 备注 |
|---|---|---|---|---|---|
| S1 UVR5 | 本地 | CPU 可跑，有 N 卡更快 | 10–20 分钟 | 中 | 老牌，模型停在 2023 版 |
| **S2 MSST-GUI** | 本地 | 建议 N 卡；RoFormer 大模型显存占用高 | 三连 11–25 分钟 | 高 | 可一键串「人声→去和声→去混响」 |
| S3 官方 Instrumental 相位相减 | 本地 Audacity | 无 | 5 分钟 | **极高（近乎无损）** | 必须无损 FLAC；不含和声 |
| S4 在线分离站 | 浏览器 | 无 | 5–10 分钟/次 | 中 | 有大小与次数限制 |

最优组合：**S3 → S2**。先用相位相减拿到无损原始人声，再让 MSST 只做「去和声 + 去混响」的轻活。

**模块二：音色转换（核心变量）**

| 方案 | 位置 | 工具要求 | 耗时 | 音质预期 | 主要风险 |
|---|---|---|---|---|---|
| M1 在线 Space | 云端 | 零安装 | 单次 10–40 分钟 | 中低 | **单次上限 100 秒**；2023 年的 Space 可能已休眠 |
| **M2 本地 sovits 4.0** | 本地 | N 卡更佳（CPU 也可，见 4.1） | 装环境 1–3 小时；推理全曲 2–3 分钟（CPU） | 中高 | 版本必须 4.0，4.1 加载报错 |
| M3 本地 RVC | 本地 | 一键整合包，显卡要求最低 | 装机 10 分钟；推理 3–8 分钟 | 中 | 说话素材训练，长音/高音弱 |
| M4 本地 DDSP 6.2/6.3 | 本地 | 训练需 4G 以上显存 | 训练 2–6 小时；推理快 | **高** | **无现成星瞳模型，必须自训** |
| M5 第三方在线推理站 | 浏览器 | 零安装 | 5–20 分钟 | 中 | 多为付费/限次，隐私风险 |

实测质量天花板：

- **M1 / M2 是同一套模型**，已有使用者反馈（B站 `BV1GL411h7tF` 简介）：「AI星瞳始终唱不上去或是唱不出来」「有部分口齿不清」→ 能听能发，副歌高潮会露怯。
- **M3** 作者自评「效果一般，聊胜于无」，训练素材是直播说话，长音会飘。
- **M4** 换了 `pc_nsf_hifigan` 声码器，作者称「极大提升高音性能」，并新增 `volume_smooth_size` 参数提高抗噪抗混响能力 —— 四条里唯一针对性解决「高音崩」的方案。

**模块三：后期合成**

| 方案 | 成本 | 耗时 | 适用 |
|---|---|---|---|
| P1 Adobe Audition | 订阅制 | 1–2 小时 | 专业级 EQ / 压缩 / 混响 / 波形对齐 |
| P2 Reaper | 60 天全功能试用 | 1–2 小时 | 同等能力，成本低 |
| P3 剪映专业版 | 免费 | 1 小时 | 混音够用，优势在卡点与画面 |

后期对整体可行性影响小，按预算选即可。

### 2.3 五条可执行路线

**路线 A · 零安装快验（当天出 90 秒样片）**

```
S4 在线分离  →  M1 在线 Space  →  P3 剪映
```
总耗时约 1 天，音质中低。最大风险：Space 可能已停服，**动手前先打开链接确认能上传**。

**路线 B · 标准本地**

```
S1/S2 本地分离  →  M2 本地 sovits 4.0  →  P1/P2
```
2–3 天（装环境占一半），音质中高。环境是最大卡点，装不通就退路线 C。

**路线 C · RVC 快车道（最稳）**

```
S2 MSST 分离  →  M3 RVC 一键包  →  P3 剪映
```
1–1.5 天，音质中。装环境屡次失败时的保底方案。

**路线 D · 视频同款（质量最高，周期最长）**

```
S3 相位相减  →  S2 MSST 三连  →  M4 DDSP 自训  →  P1 Audition
```
5–8 天（训练占大头），音质高。前置条件：星瞳没有公开 DDSP 模型，**必须自己训**。

**路线 E · 混合推进（本次采用）**

```
阶段一（3 天）：S3 + S2 + M2/M3  →  出完整成片
阶段二（并行 5 天）：用同一批 MSST 素材  →  训 M4
阶段三（1 天）：DDSP 训好  →  只替换「转换」环节  →  重新出片
```
核心逻辑：**不要为了等模型停下整条链**，除转换外所有环节完全复用。

### 2.4 决策树

```
你能拿到官方 FLAC 吗？
├─ 能 ─→ 用 S3 相位相减（省掉最难的分离步骤）
└─ 不能 ─→ 用 S2 MSST 三连

你手上有 NVIDIA 显卡吗？
├─ 有 ─→ 走本地路线（B / C / D）
└─ 没有 ─→ 走在线路线（A / M5），或租云 GPU

你能接受「副歌高音会崩」吗？
├─ 能 ─→ M1 / M2 / M3 任一，1–3 天出片
└─ 不能 ─→ 必须走 M4（DDSP 自训），准备 5–8 天

你的成片多长？
├─ 60–90 秒 ─→ M1 在线 Space 可行（100 秒以内一次搞定）
└─ 完整 6:39 ─→ M1 必须切 5 段以上，不划算，改本地
```

| 项 | 值 |
|---|---|
| Python | 3.13.14（独立 `.venv`，与系统 Python 隔离） |

### 3.2 复现步骤

```bash
# 1) 建独立虚拟环境（Python 3.13）
python -m venv .venv

# 2) 只装推理核心依赖 —— 绝对不要整体装 requirements.txt
#    里面混着训练依赖（sageattention / bitsandbytes / wxpython），必失败
.venv\Scripts\python.exe -m pip install -i https://pypi.org/simple ^
    PyQt5 soundfile librosa numpy scipy wandb beartype

# 3) 换成 CUDA 版 torch（按 cu126 通道配对安装）
.venv\Scripts\python.exe -m pip uninstall -y torch torchaudio
.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cu126 ^
    torch==2.11.0 torchaudio==2.11.0

# 4) 模型放 pretrain/，同名配置放 configs/，然后双击启动
```

装完不需要改任何设置 —— 启动时检测到 CUDA 会自动使用，日志打印 `Using device: cuda:0`。
需要临时强制用 CPU（例如显存被占用）时加 `--force_cpu`。

### 3.4 实测性能

同一段 30 秒音频、同一个模型（BS-RoFormer 317），CPU 与 GPU 对照：

| 运行方式 | 耗时 | 实时倍率 |
|---|---|---|
| CPU 版 torch | 861.75 秒（14 分 22 秒） | 0.029× |
| **CUDA 版 torch** | **44.32 秒** | **0.68×** |
| 加速比 | **19.4 倍** | — |

按 GPU 速度跑完整首 5:57：

| 阶段 | 模型 | 实测耗时 |
|---|---|---|
| ① 人声分离 | BS-RoFormer 317 | **6 分 07 秒** |
| ② 去和声 | MelBandRoformer karaoke | **2 分 54 秒** |
| ③ 去混响 | deverb BS-RoFormer | **2 分 26 秒** |
| **三连合计** | — | **约 11 分 30 秒** |

两种运行方式输出一致（峰值 −0.78 dBFS、RMS −16.76 dBFS 完全相同），说明 GPU 通路没有精度损失。

### 3.5 三连分离的正确顺序

GUI 里从上到下依次启用，**串联**推理：

```
① 人声模型   → 输出 Vocals（主唱 + 和声 + 混响）
② 和声模型   → 去除伴唱，留下主唱
③ 去混响模型 → 去除空间感，得到干声
```

**②③ 不是并列的，是串联的。** 必须喂 ② 的输出给 ③，不能拿整首歌直接进 ③。
输出目录按「模型名/Vocals.wav」结构保存，取最后一层的 `Vocals.wav` 即最终干声。

### 3.6 输出文件与电平

源文件：`《女神异闻录3》片尾曲「你的记忆」.wav`，2006 原版，**5:57.70，48kHz/24bit**。
四轨产物统一 **5:57.70 · 44100 Hz · 立体声 · 32bit float WAV**。

| 文件名 | 对应模块 | 里面是什么 | 用途 |
|---|---|---|---|
| `A_人声分离_主唱+和声+混响` | 人声分离 | 主唱 + 伴唱 + 原曲混响，**没有伴奏** | 需要保留和声时用 |
| `B_和声分离_主唱去伴唱` | 和声分离 | 只剩主唱，伴唱剥离；仍带原曲混响 | **换声主力素材（推荐）** |
| `C_混响和声分离_干声` | 混响和声分离 | 主唱、无伴唱、**已去混响** | 需要自己加混响时用 |
| `D_伴奏_Instrumental` | 人声分离（扣人声） | 纯伴奏 | 成片 backing track |

带 `_规范化` 后缀的副本：原始输出峰值会过冲到 +0.1 dBFS，直接转 16bit 会削波。规范化版统一压到 **−1.0 dBFS**，**交付和导入剪辑软件时用这个**。

| 文件 | 原始峰值 | 规范化后 | RMS |
|---|---|---|---|
| A_人声分离 | +0.12 dBFS | −1.00 dBFS | −18.19 dBFS |
| B_和声分离 | +0.16 dBFS | −1.00 dBFS | −19.05 dBFS |
| C_混响和声分离 | −0.36 dBFS | −1.00 dBFS | −19.79 dBFS |
| D_伴奏 | +0.99 dBFS | −1.00 dBFS | −13.35 dBFS |

**互补性验证**：`A 人声 + D 伴奏` 与原曲逐采样比对，相关系数 **1.00000000**、最大误差 **0** —— 两者是严格的数学互补关系（伴奏 = 原曲 − 人声），不是独立预测。

**换声该用哪一轨**：

| 场景 | 推荐 |
|---|---|
| 通用（默认） | **B_主唱去伴唱** —— 保留一点混响更自然，转换后不会太干 |
| 后面要精细加混响 | C_干声 —— 最干净，但去混响可能削薄气声 |
| 想保留原曲伴唱作和声层 | A_人声分离 —— 但转换时伴唱也会被换音色 |

建议做 A/B 对比：同一段副歌分别用 B 和 C 转一遍，听齿音和气声哪个更完整。B 通常更自然，C 在混响特别大的段落容易发虚。

单声道化注意：**源是 48kHz，sovits 要 44.1kHz，这里已经是 44.1kHz 不用再转**；RVC 模型是 48kHz，需要升采样回去。

### 3.7 踩坑（6 条）

1. **pip 默认源不可用** —— 必须显式 `-i https://pypi.org/simple`。
2. **`requirements.txt` 不能整体安装** —— 是训练依赖，含 `sageattention`、`bitsandbytes`、`wxpython` 等必失败包；推理只需核心十来个。
3. **`utils/settings.py` 顶层 import 了 wandb** —— 不装 wandb 连推理都起不来。

### 4.4 参数说明

| 参数 | 值 | 含义 |
|---|---|---|
| `-m` | `logs/xingtong20/G_99200.pth` | 模型权重 |
| `-c` | `configs/xingtong20.json` | 配置（必须配套） |
| `-n` | 文件名 | 放在 `raw\` 下的 wav，**不带 .wav** |
| `-t` | `0` | 变调半音。原唱与目标都是女声 → **0** |
| `-s` | `xingtong20` | 说话人名，**必须与 config 里 `spk` 的键一致**；填「星瞳」会报错 |
| `-cm` | `.../kmeans_10000.pt` | 聚类模型路径（是 `-cm` 不是 `-cr`） |
| `-cr` | `0.5` | 聚类占比 0–1，越高越像目标音色，也越容易不稳 |
| `-sd` | `-50` | 静音切片阈值。**−50 保留呼吸气口**，−40 更激进 |
| `-wf` | `wav` | 输出格式，默认 flac |

**调优对照表**

| 症状 | 调整 |
|---|---|
| 齿音、气声丢太多 | `-sd` 改 **−55 / −60**，让切片更宽松 |
| 音色不够像星瞳 | `-cr` 提到 **0.6–0.7**，但监听有没有金属感 |
| 高音段破音 / 发飘 | `-cr` 降到 **0.3**，或那一段单独用 `-t -1` 试 |
| 咬字含糊 | `-sd` 改 **−40**，减少切片碎块 |
| 整体太轻 / 太响 | 输出后统一做峰值规范化，不要在模型端调 |

### 4.5 已知坑（7 条）

1. **不要用 `-a/--auto_predict_f0`** —— 代码里是 `type=bool`，任何非空字符串都会变 `True`，歌声开自动预测会**严重跑调**。保持默认关闭。
2. **输入必须是 44.1kHz、单声道** —— config 里 `sampling_rate: 44100`。`B_和声分离` 正好是 44.1kHz 立体声，脚本会自动转单声道，但**别喂 48kHz**。
3. **输出比输入响约 5 dB** —— 实测 −17.55 → −12.12 dBFS，是模型内部的响度处理，正常。混音时压回来。
4. **静音段会被自动跳过** —— 这首只有 **54.4%** 的时长有主唱，切片器会打 `jump empty segment` 并跳过，**不是漏转**。
5. **不要装 so-vits-svc 4.1** —— 4.1 编码器锁死 768 维（`vec768l12`），这套权重是 256 维，加载会失败。
6. **.bat 里不能写中文** —— Windows cmd 按当前代码页逐字节解析批处理，UTF-8 中文会把命令切成碎片（报错形如 `'nce_main.py' 不是内部或外部命令`），`chcp 65001` 也救不了（解析发生在 chcp 生效前）。**解法**：.bat 保持纯 ASCII，中文输出与路径处理交给 Python。
7. **CUDA 版 torch 下不动** —— `download.pytorch.org` 及国内镜像在本网络被限速到约 150 KB/s，2.6 GB 要 5 小时。CPU 实测 3.3 倍速已够用。

其他安装期踩坑：

- **原仓库已无 4.0 分支**，releases 也是空的，历史被重置 → 用 `justinjohn0306` 的 fork（270 星，唯一保留 `f0_decoder`，与权重完全对得上）。
- **`uv venv` 没有 pip** → `python -m ensurepip` 或 `uv pip`。
- **torchaudio 2.0.1 在 PyPI 上依赖 torch==2.0.0**，与 torch 2.0.1 冲突 → 正确配对是 **torch 2.0.1 + torchaudio 2.0.2**。
- **pyworld 0.2.5 没有 win cp310 轮子** → 用 **0.3.4**（有预编译轮子，接口兼容）。

#### 6.3.4 留白校准（最关键的一节）

**蓝版的「留白」不是空白，是「有颜色的空」**，承担画面 60% 面积和全部视觉重量：

| 区域 | 占比 | 蓝版实际内容 | 红版错误做法 | 红版应该 |
|---|---|---|---|---|
| 左侧大空景 `x 0–560` | ~50% | 深蓝 → 亮青的**对角渐变**，有雾状层次 | 纯白纸 | 深酒红 → 玫粉的对角渐变 |
| 顶部横带 `y 0–120` | ~20% | 整条深海军蓝 | 纯白 | 整条深酒红 |
| 右上角 `x 900–1080, y 0–200` | ~8% | 深蓝，头部压在深色里 | 纯白 ← **最刺眼** | 深酒红 |
| 人物右缘收边 | ~5% | 深蓝渐变到画面边缘 | 纯白 | 深红渐变到边缘 |
| 脖颈后方 `x 700–820, y 300–450` | ~4% | 最亮亮青，人景分离靠它 | 纯白 | 最亮玫粉 |
| 底部亮带 `y 480–608` | ~18% | 亮青崖壁 + 水面波光 | 暗红色块 | 亮玫粉崖壁 + 光带 |

> ❌ 留白要和图1 一样
> ❌ 背景保持简洁，大量留白
> ✅ 画面左侧这一大片空景是**渐变的天幕**，有颜色、有厚度，不是白纸
> ✅ 整个画面每一个角落都有颜色，没有纯白的空白区

#### 6.3.5 右下角的白色收口

蓝版右下 `x 750–1080, y 380–608`（约右下四分之一）是**唯一真白**：上边界是一条从人物腰部向右下角上扬的**柔和斜向过渡带**，左边界被身体轮廓咬进去，内容接近 `#FFFFFF`（只有极淡青灰 `#EAF6FA` 暗示衬衫褶皱），作用是让人物下半身「沉进光里」。

蓝版的背景结构本质是**对角分割**：

```
左上 2/3：实色渐变（深蓝 → 亮青）   ← 重
右下 1/3：白（人物沉入）            ← 轻
分界线：一条斜向柔和过渡带
```

**红版不能照搬纯白**：蓝版成立是因为人物穿白衬衫，衬衫融进白里消失得很优雅；红版是**黑外套 + 黑发**，纯白衬黑剪影等于刀切，视觉重心全压到人物，左侧刚铺好的渐变全废。
正确处理：右下角改**极浅暖粉**（`#FCEFF1` → 向外提亮到近白），保留「沉入光里」的明度关系，同时柔化外套下摆边缘。

提示词补丁（插在背景段落里）：

```

最后一句「只有右下角这一块是浅的」必须留着，否则会被理解成整体调亮，又回白纸。

#### 6.3.6 质感锁定（针对第 8 版失败）

| 项目 | 目标（蓝版 / C 图） | 第 8 版实际 | 判定 |
|---|---|---|---|
| 渐变质感 | 平滑均匀，像渐变工具拉出来的，**零纹理** | 雾状颗粒、云团状浑浊，像水彩或烟熏 | ✗ 致命 |
| 结构 | 顶部 1/3 近乎**纯色**，中段过渡，底部亮 | 从顶部就开始雾化，无纯色顶带 | ✗ |

| 花瓣 | 有厚度、卷曲、清晰边缘 | 仍是圆形血滴，更模糊 | ✗ 完全没生成 |
| 右上角 | 深色 | 全白 | ✗（可接受） |

**根因：提示词里写了「有雾一样的通透层次」。**

> **蓝版的「透」是颜色透，不是雾气的透。**

```

#### 6.3.7 双区域分步（最终方案）

**原则：两个区域必须分两次做，每次只涂一个遮罩、只贴一条提示词。** 一次涂两块，模型会把两段描述混着理解，背景的「平滑渐变」会被带到人物脸上。顺序：**先背景，后服装**。

**区域 A：人物左侧背景**

> 遮罩：只涂人物左侧整片空白（左上、左中、左下），**不碰人物任何部位**，也不涂右下角白色。

```

平滑渐变，无噪点、无颗粒、无烟雾、无水彩、无纹理，日系动画背景美术。
```

为什么这版不容易跑偏：把三个「不可复制的特征」都点了名 —— 顶部纯色块、珊瑚礁的镂空与孤立碎块、气泡的三组位置。有了具体形状约束，模型就没空间自由发挥。

**区域 B：胸部服装补全**

> 问题：人物左侧胸前（约 `x 690–780, y 460–560`）黑色外套被一块白色缺口侵入，边缘在白色里突然中断，翻领没有收口，像被裁掉一块。
> 遮罩：只涂缺口及紧邻的黑色外套边缘，向上不超过锁骨，不碰脸和项链。

```
只补全人物胸前的黑色外套，头部、脸、头发、脖子、项链全部不动。

胸前左侧的黑色外套目前被白色的缺口切断，边缘不完整。请补成一件结构完整的外套：从肩线自然延续到胸口，贴胸处有一道清晰的翻领边缘，翻领内侧露出深红色内衬，外套的下缘自然收口，不要在白色里突然中断。

画法保持极简动画风格：纯黑色块面 + 白色高光 + 深红内衬，边缘是清晰锐利的线，没有褶皱细节。不要增加衬衫、领带、纽扣、口袋、花纹等新元素。立领造型和红宝石项链保持原样。
```

若要改成「白衬衫 + 领带」造型，把中间段替换为：

```
胸前补成白衬衫加黑白条纹领带：衬衫领口敞开，露出锁骨，领带从领口垂下，外面套黑色立领外套，外套翻领内侧是深红色内衬。
```

注意这是**改设定**不是修复：加了衬衫领带后，人物气质与「纯黑外套无内衬」的原设定不一致，两侧红挑染也会显得孤单。建议先只补外套。

**验收清单**

区域 A：顶部 1/4 是纯色块；珊瑚礁有镂空和右下侧孤立碎块；顶缘有更亮高光边；三组花瓣数量位置对得上气泡原位；整片无颗粒无雾感。
区域 B：外套在胸前不再被白色切断；翻领有结构线；没多出衬衫/纽扣；项链和领口没变形。

#### 6.3.8 八轮迭代的复盘（三条最值钱）

1. **自然语言里的「氛围词」会劫持质感。** 「雾一样的通透」→ 直接把平滑渐变变成烟雾水彩。想控质感只能写**反向约束**（无噪点、无颗粒、无云团）并给参照图。
2. **「留白」在中文语境里等于「别画」。** 想要有颜色的空，必须写成「渐变的天幕」「每个角落都有颜色」，并明确点名哪一块才是真浅色。
3. **生成模型的能力边界要早认。** 连续两轮不对，就该切 Plan B 手动合成：

```
① 纯蓝背景图整体色相旋转到红（任何绘图软件 10 秒，质感 100% 保留）
② 把人物从纯白底上抠出来（背景是纯白，一键选择即可）
③ 人物层叠到红化后的背景上，右下角保留原图白
```

这条路的产出质量**稳定高于任何抽卡结果**，因为背景每一处都是原图的精确复制，只换了色相；抽卡的随机性永远在形状和质感上打赌。

## 7 字幕工程

### 7.1 目标与做法

从干声轨做**能量包络分析**，粗略定位每个乐句的起止时间，给后续打轴（SRT / ASS）提供初始切点。

做法：按 20 ms 跳、40 ms 窗算 RMS → 转 dB → 双阈值分段（阈值 + 最短时长 0.30 s + 最小间隙 0.28 s）→ 合并小间隙 → 丢掉过短段。

### 7.2 完整脚本 `detect_phrases.py`

```python
# -*- coding: utf-8 -*-
"""从干声轨做能量包络分析，粗略定位每个乐句的起止时间。"""
import struct, math, sys
from array import array
from operator import mul

def wav_info(path):
    with open(path, 'rb') as f:
        f.read(12)
        sr = ch = bps = None
        while True:
            b = f.read(8)
            if len(b) < 8:
                break
            cid, cs = struct.unpack('<4sI', b)
            if cid == b'fmt ':
                d = f.read(cs)
                fmt, ch, sr, br, ba, bps = struct.unpack('<HHIIHH', d[:16])
            elif cid == b'data':
                return dict(sr=sr, ch=ch, bps=bps, data_off=f.tell(), data_len=cs)
            else:
                f.seek(cs, 1)

def envelope(path, hop_ms=20, win_ms=40):
    info = wav_info(path)
    sr, ch = info['sr'], info['ch']
    hop = int(sr * hop_ms / 1000)
    win = int(sr * win_ms / 1000)
    hop_bytes = hop * ch * 4
    win_n = win * ch
    env = []
    with open(path, 'rb') as f:
        f.seek(info['data_off'])
        total = info['data_len']
        read = 0
        while read + hop_bytes <= total:
            buf = f.read(hop_bytes)
            if len(buf) < hop_bytes:
                break
            a = array('f')
            a.frombytes(buf)
            n = min(win_n, len(a))
            seg = a[:n]
            ms = sum(map(mul, seg, seg)) / max(1, len(seg))
            rms = math.sqrt(ms) if ms > 0 else 0.0
            db = 20 * math.log10(rms) if rms > 1e-9 else -120.0
            env.append((read / 4 / ch / sr, db))
            read += hop_bytes
    return env

def segments(env, thr_db, min_dur=0.30, min_gap=0.28, pad=0.05):
    raw = []
    start = None
    for t, db in env:
        if db >= thr_db:
            if start is None:
                start = t
        else:
            if start is not None:
                raw.append([start, t])
                start = None
    if start is not None:
        raw.append([start, env[-1][0]])
    merged = []
    for s, e in raw:
        if merged and s - merged[-1][1] < min_gap:
            merged[-1][1] = e
        else:
            merged.append([s, e])
    merged = [[s, e] for s, e in merged if e - s >= min_dur]
    return merged

if __name__ == '__main__':
    path = sys.argv[1] if len(sys.argv) > 1 else '输出/C_混响和声分离_干声.wav'
    env = envelope(path, hop_ms=20, win_ms=40)
    dbs = sorted(d for _, d in env)
    def pct(p):
        return dbs[min(len(dbs) - 1, int(len(dbs) * p))]
    peak = max(dbs)
    print('frames', len(env), 'peak %.1f  p5 %.1f  p50 %.1f  p90 %.1f  p95 %.1f p99 %.1f'
          % (peak, pct(0.05), pct(0.50), pct(0.90), pct(0.95), pct(0.99)))
    for thr in (-45, -40, -35, -30, -25):
        segs = segments(env, thr)
        print('thr %d -> %d segs' % (thr, len(segs)))
    thr = float(sys.argv[2]) if len(sys.argv) > 2 else -38.0
    segs = segments(env, thr)
    print('--- thr', thr, 'segs', len(segs))
    for i, (s, e) in enumerate(segs, 1):
        print('%3d  %7.2f  %7.2f   dur %5.2f   gap-before %5.2f'
              % (i, s, e, e - s, s - segs[i - 2][1] if i > 1 else s))
```

### 7.3 用法与限制

```bash
python detect_phrases.py 输出/C_混响和声分离_干声.wav -38
```

- 第二个参数是判定阈值（dB）；先看脚本自动打印的 −45…−25 各档段数，挑段数最接近歌词行数的那一档，再手调。
- **只吃 32bit float WAV**（代码里按每样本 4 字节读），所以输入必须是 MSST 的原始输出，不能用 16bit 规范化副本。
- 输出只是「能量块」不是「唱词」：换气、气声、伴奏残留都会切出额外的段，**仍需人工按歌词删改**。这首只有 54.4% 时长有主唱，间奏处会切出长空档，属正常。
- 未做的部分：没有把结果写成 SRT/ASS，需要按第 9 章歌词人工配对。

### 11.1 已验证的结论

1. **MSST 三连在这台机器上是可用的**：GPU 19.4× 加速，全曲 11 分半，A+D 与原曲严格互补 —— 说明分离环节没有引入臆造内容，后续所有素材都干净。

## 附录 B 可复用经验

跨项目通用，下次不必重新踩：

1. **Windows 的 .bat 里绝不能出现中文**（含注释和 echo）。cmd 按代码页逐字节解析，`chcp 65001` 也救不了。所有中文逻辑放 Python。
2. **torch 与 torchaudio 版本必须成对**，且 PyPI 上的依赖声明经常把版本拉回旧版（torchaudio 2.0.1 硬依赖 torch 2.0.0）。先查清配对再装。
3. **不要整体 `pip install -r requirements.txt`**：AI 项目的 requirements 常年混着训练依赖（sageattention / bitsandbytes / wxpython / deepspeed），推理只需十几项。
4. **装不上的纯 Python 包可以手工解压进 site-packages**（fairseq 这类），前提是确认缺的 Cython 模块是懒加载、当前路径用不到。
5. **CUDA 版 torch 下不动就先用 CPU**：本机 150 KB/s、2.6 GB 要 5 小时；而 sovits CPU 3.3 倍速已够用。判断标准是「单次推理时间 vs 下载时间」。
6. **mel-band RoFormer 的 karaoke 模型对和声极有效**，比 UVR 的老模型强一档；但它激进，人声本身也会被削一点，最好保留原始 A 轨做对比。
7. **算「互补性」而不是「听感」**：人声 + 伴奏逐采样相加等于原曲（误差 0），才能证明分离没有臆造内容。这是唯一客观的分离质量检验。
8. **生成式修图里，氛围形容词是最大的不确定性来源**。「雾」「通透」「留白」「简洁」都会被模型解读成具体的质感分支。控质感只能靠反向约束 + 参考图。
9. **抽卡两轮不对就换手动合成**。色相旋转 + 抠图 + 图层合成，十分钟出稳定结果，胜过十轮抽卡。
10. **归档时按「可重算」与「不可再生」分类**：能靠文档十几分钟重算的（环境、模型、中间文件）全删；不可再生的（成品、歌词、主视觉）留。文档要把重装步骤写到「照着点就行」的程度，否则删掉的东西就真的没了。
